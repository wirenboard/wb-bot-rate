# wb-bot-rate

Плагин Discourse. Снимает форумное ограничение частоты постинга внутри личных
диалогов с ИИ-ботом, не трогая остальной портал.

## Зачем

Клиенты переписываются с `@AIbot` как в мессенджере — короткими репликами по
несколько в минуту. Ядро применяет к ним `rate_limit_create_post` (5 секунд на
support.wirenboard.com) и отбивает сообщение с кодом 429. Человек видит это как
поломку сайта. За неделю замера все девять отказов у живых клиентов пришлись на
диалоги с ботом, один клиент после отказа не дописал и ушёл.

## Как работает

Ограничитель живёт в `RateLimiter::OnCreateRecord`: `Post` вешает
`after_create → default_rate_limiter.performed!`, а тот кладёт отметку времени
в список Redis. Событие `:post_created` приходит уже после этого, поэтому
плагин не отключает ограничитель, а **откатывает** его — `rollback!` снимает
только что положенную отметку (`LPOP`). Следующее сообщение в окно не упирается.

Приём взят из ядра: так делает встроенный `discourse-narrative-bot`
(`lib/discourse_narrative_bot/actions.rb`, метод `reset_rate_limits`).

Откат срабатывает, только если выполнено всё сразу:

- `wb_bot_rate_enabled = true`;
- тема личная (`private_message`);
- **среди участников темы есть учётка ИИ-бота** — проверяется по
  `DiscourseAi::AiBot::EntryPoint.all_bot_ids` (агенты `discourse-ai` плюс
  пользователи включённых `LlmModel`);
- автор поста не персонал и не сам бот;
- пост создан не через `skip_validations` (там отметки нет, откатывать нечего);
- не исчерпан потолок откатов.

Проверяется именно участие бота в теме, а не «тема личная»: обычная переписка
между людьми послабления не получает.

### Про потолок

Счётчик откатов лежит в Redis под ключом
`wb-bot-rate:rollbacks:<topic_id>:<user_id>` и живёт ровно длину окна
ограничителя. Внутри одного окна разрешено не больше `wb_bot_rate_max_rollbacks`
откатов.

Практический потолок получается **`max_rollbacks + 1` сообщений за окно**: столько-то
откатов плюс одно сообщение, которое займёт ограничитель. При значениях по
умолчанию (потолок 2, окно 5 с) это 3 сообщения за 5 секунд, дальше обычный 429.

## Настройки

| настройка | по умолчанию | назначение |
|---|---|---|
| `wb_bot_rate_enabled` | `false` | выключатель, гасит поведение целиком |
| `wb_bot_rate_max_rollbacks` | `2` | потолок откатов за окно, по теме и пользователю. `0` гасит послабление, не выключая плагин |
| `wb_bot_rate_bot_usernames` | пусто | какие ботовые учётки считать. Пусто — все ИИ-боты установки |

`wb_bot_rate_bot_usernames` нужен там, где ботов несколько, а послабление
предназначено одному. Список **пересекается** с `all_bot_ids`, а не заменяет
его: указать обычного пользователя и выдать ему послабление нельзя. Обратная
сторона — опечатка в имени даёт пустое пересечение и молча выключает послабление.

## Зависимости

`discourse-ai` — нужен для `DiscourseAi::AiBot::EntryPoint`. Если плагина нет
или `discourse_ai_enabled = false`, wb-bot-rate ничего не делает.

Замечание: `DiscourseAi::AiBot::Playground.is_bot_user_id?` для этой задачи не
годится — это просто `user_id <= 0`, под него попадают `system` (-1) и
`discobot` (-2). Нужен именно `EntryPoint.all_bot_ids`. Заодно
`LlmModel.enabled_chat_bot_ids` возвращает **id записей LlmModel**, а не
пользователей; user_id из них достаёт `EntryPoint`.

## Тесты

`spec/lib/wb_bot_rate/relief_spec.rb` — 21 пример, все зелёные на Discourse
`2026.4.0` с загруженным `discourse-ai`.

Discourse грузит плагины только из своего каталога `plugins/`, поэтому перед
прогоном плагин надо положить внутрь чекаута дискурса:

```bash
# на хосте: source — этот каталог, DISCOURSE — чекаут дискурса
rm -rf "$DISCOURSE/plugins/wb-bot-rate"
cp -r wb-bot-rate "$DISCOURSE/plugins/wb-bot-rate"

# в контейнере, от пользователя discourse
cd /src && LOAD_PLUGINS=1 RAILS_ENV=test bundle exec rspec plugins/wb-bot-rate/spec
```

Симлинк не годится: цель окажется вне bind-mount `/src` и внутри контейнера
ссылка будет битой. Копию после прогона лучше удалять — иначе она незаметно
разойдётся с источником, и спеки отработают против старой версии. Правильное
решение — отдельный bind-mount каталога плагина в `/src/plugins/wb-bot-rate`,
но он требует пересоздания контейнера.

Спеки подменяют `RateLimiter` и `EntryPoint.all_bot_ids`, то есть проверяют
**решение** «звать `rollback!` или нет», а не то, что откат действительно
освобождает ограничитель. Это проверено отдельно, вживую по HTTP — см.
`docs/01_rate_limit_relief.md` в рабочем репозитории.
